# LINUX DO macOS 阅读器 UI 优化建议

> 文档状态：优化建议
> 适用范围：`macos-reader/` 原生 macOS 阅读器
> 更新时间：2026-08-05
> 设计基线：Apple Human Interface Guidelines、macOS 系统应用、仓库根目录 `AGENTS.md`

## 1. 结论先行

当前阅读器的基础方向是正确的：已经采用 `NavigationSplitView` 三栏结构、系统语义色、原生 `List`、连续文档式详情页，并通过 `DesignSystem.swift` 统一了主要视觉常量。后续优化建议以“减少认知负担、提高长帖阅读效率、加强 macOS 操作感”为主，不建议重新引入网页式卡片或大面积装饰。

建议按以下优先级推进：

| 优先级 | 目标 | 主要收益 |
| --- | --- | --- |
| P0 | 明确三栏信息层级、统一状态反馈、收敛工具栏操作 | 用户更快知道当前在哪里、发生了什么、下一步能做什么 |
| P1 | 增强主题列表扫描和长帖阅读导航 | 降低找主题、找楼层、回到上次阅读位置的成本 |
| P1 | 完善键盘、焦点、动态字体和无障碍体验 | 让应用更符合 macOS 高强度使用习惯 |
| P2 | 提升个性化阅读设置和多窗口体验 | 形成稳定的长期阅读工作流 |

## 2. 当前 UI 判断

### 2.1 已有优势

- `ContentView` 已按最新、热门、分类、通知、站点和设置组织主要场景，整体信息架构清楚。
- `SidebarView` 使用 `.sidebar` 列表样式，账号、通知和分类集中在左侧，符合 macOS 应用的导航习惯。
- `TopicListView` 使用平面列表、原生选中态、下拉刷新和底部状态栏，已经摆脱网页式大卡片布局。
- `TopicDetailView` 使用单一连续阅读 WebView 承载主题内容，解决了多 WebView 嵌套滚动和长帖性能问题。
- `DesignSystem.swift` 已集中维护栏宽、阅读最大宽度、圆角、分隔线和通用标签，应继续作为所有新 UI 的入口。
- 加载、错误、空选择、分页和登录失败等状态基本齐全，后续应重点统一表达方式和操作路径。

### 2.2 主要问题

1. **主题详情的上下文信息不足。** 当前标题主要依赖导航栏，用户进入长帖后不容易快速确认分类、作者、回复数量、更新时间和阅读进度。
2. **长帖导航仍偏弱。** 已有分页和目标楼层加载，但缺少明显的楼层跳转、目录/楼层概览、回到上次阅读位置等入口。
3. **工具栏操作较多，主次关系还可以更清楚。** 刷新、兼容网页、回复都属于不同层级的动作，建议将低频操作放入菜单，将高频动作保留在工具栏。
4. **状态提示分散。** 登录状态变化、网络失败、分页加载、帖子操作结果分别在不同位置出现，用户需要在多个区域寻找反馈。
5. **主题列表仍有进一步提升扫描效率的空间。** 标题、作者、分类、时间、回复数和高亮状态需要更稳定的列级关系，窄窗口下也要避免信息互相挤压。
6. **部分颜色仍直接表达成功或警告。** 关注、错误、未读和已接受答案需要同时提供文字或 SF Symbols，不能只依赖绿色、橙色等颜色区分。
7. **交互细节还可以更 macOS 化。** 需要系统性补充焦点态、键盘上下移动、默认按钮、取消按钮、右键菜单和窗口尺寸下的布局验证。

## 3. 设计目标与验收指标

### 3.1 设计目标

- 用户打开应用后，在 3 秒内能理解当前所在的浏览范围、当前选中的主题和登录状态。
- 用户可以只用键盘完成“切换导航项、选择主题、滚动阅读、刷新、打开搜索或回复”。
- 长帖中用户能快速完成“跳到指定楼层、回到未读位置、继续加载、回到主题顶部”。
- 轻量状态不遮挡正文；错误状态提供明确原因和唯一主操作；操作成功反馈不打断阅读。
- 浅色、深色、系统字体放大和最小窗口尺寸下，文字不截断、不重叠、不依赖固定高度。

### 3.2 建议指标

| 指标 | 建议目标 |
| --- | --- |
| 首屏可理解时间 | 默认窗口打开后 3 秒内完成当前区域识别 |
| 主题列表扫描 | 单个列表行至少稳定呈现标题、作者/参与者、时间、回复数四类信息 |
| 长帖定位 | 从详情页打开楼层跳转到目标楼层不超过 2 次主要操作 |
| 阅读恢复 | 重新打开已读主题后，可恢复到上次可识别的楼层或位置 |
| 键盘操作 | 主要浏览路径无需鼠标即可完成 |
| 最小窗口 | 默认窗口和最小窗口均无裁切、重叠、横向溢出 |
| 无障碍 | 重要状态不只依赖颜色，按钮和图标均有可读标签 |

## 4. 信息架构建议

### 4.1 保留三栏，但明确每栏职责

| 区域 | 职责 | 建议呈现 |
| --- | --- | --- |
| 侧栏 | 全局范围切换 | 最新、热门、分类、通知、账号、设置 |
| 主题列表 | 同一范围内的主题扫描和选择 | 主题标题、作者、时间、回复数、未读/高亮状态 |
| 详情 | 连续阅读和主题操作 | 主题摘要、楼层流、阅读导航、回复入口 |

侧栏不应承担主题级操作；主题列表不应承担正文操作；详情页的回复、跳楼、书签等操作应围绕当前主题组织。这样可以避免同一动作在多个栏位重复出现。

### 4.2 详情页增加轻量主题头部

在 `TopicDetailView` 的正文上方增加一个非卡片式主题头部，建议包含：

- 主题标题，允许最多两行，超出后完整标题通过辅助信息或悬停提示提供。
- 分类标签、主题创建者、创建时间、回复数/浏览数等次要信息。
- 当前阅读状态，例如“已读至 #43”或“还有 12 层未读”。
- 低频操作放入菜单，例如复制链接、在网页中打开、分享、标记已读。

主题头部应使用正文流的一部分，不要套用大圆角卡片。标题和正文之间保持 16 或 24 的系统间距，避免占据过多首屏高度。

### 4.3 长帖阅读导航

建议以逐步增强方式实现：

1. P0：在详情底部状态栏显示当前已加载楼层范围、总楼层数和加载状态。
2. P1：增加“跳转楼层”按钮，使用 Sheet 或 Popover 输入楼层号，支持回车确认和 Esc 取消。
3. P1：增加“回到上次阅读位置”入口；目标楼层加载完成后，使用轻量定位提示，不强制弹窗。
4. P2：增加按楼层号排列的导航条或缩略目录，仅在长帖中显示，短帖不增加额外噪声。

## 5. 分区域优化建议

### 5.1 侧栏 `SidebarView`

**建议：**

- 保留“浏览 / 账号 / 分类”分组，但让当前选中项始终使用系统选中态，不额外绘制背景。
- 登录用户行继续支持点击进入资料，但将“会话已连接”从单独颜色状态改为 `checkmark.circle.fill + 原生会话已连接` 的图标和文字组合。
- 未读通知除了数量徽章外，增加侧栏项的可访问性描述；数量为 0 时不显示空徽章。
- 分类数量使用 `.tertiary`，当窗口较窄时优先保证分类名称，不要让数量挤压名称。
- “检查登录状态”属于低频维护操作，建议放入账号区域的菜单或设置页；侧栏保留登录失效时的明确状态提示。
- 侧栏底部的 App 标识可以保留，但不应占用过多高度；窗口变窄时优先压缩品牌说明，而不是影响分类列表。

**验收：**

- 侧栏宽度在 `sidebarMinWidth` 到 `sidebarMaxWidth` 范围内，名称、徽章和数量不重叠。
- 键盘焦点可以遍历所有导航项，当前项不依赖颜色才能识别。
- 分类加载、失败、重试和空数据状态使用同一套状态组件。

### 5.2 主题列表 `TopicListView` / `TopicRowView`

**建议：**

- 将一行信息稳定分成“标题区 + 辅助信息区 + 指标区”，不要依赖多个 `Spacer` 在窄窗口下自由挤压。
- 标题使用 `.headline` 或等价系统文本样式；作者、分类、时间使用 `.caption` / `.secondary`；回复数和阅读数使用等宽数字。
- 未读、关注作者、关键词命中、已读等状态应组合使用左侧强调线、SF Symbol 和文字标签，避免多种背景色叠加。
- 长标题最多显示两行；辅助信息允许收缩，但标题不应被回复数或时间截断到不可识别。
- 选中行的内容对比度必须在浅色和深色模式下清晰，关注高亮只能作为次级背景，不得覆盖系统选中态。
- “加载更多”建议使用列表底部原生状态行，按钮只在确实有更多内容时出现；加载中状态保持行高稳定。
- 列表底部状态栏应区分“最后更新时间”“有新内容待刷新”“当前主题数量”，避免将多个状态拼成难读的一句话。

**建议增加的交互：**

- 上下箭头移动主题选择，Enter 打开或确认当前主题。
- `⌘R` 刷新当前列表；刷新中禁用重复请求并保留当前选择。
- 右键菜单提供“标记已读、复制链接、在网页中打开”等主题级操作。
- 双击或辅助功能操作打开主题时，保持当前列表选择和滚动位置。

### 5.3 主题详情 `TopicDetailView`

**建议：**

- 保留连续文档流，不恢复“每层一个大卡片”。楼层之间使用留白、轻分隔线和稳定的作者信息层级。
- 顶部增加主题头部，底部保留轻量分页状态栏；两者均不应遮挡正文内容。
- 工具栏保留高频动作：刷新、回复；“兼容网页”以及复制链接、分享、标记已读等放入 `Menu`。
- 回复按钮根据登录状态显示“回复”或“登录后回复”，但登录提示应在操作失败或需要权限时出现，避免在每个区域重复提醒。
- 帖子操作优先使用楼层右侧的 `Menu`，低频危险操作如删除、举报必须继续使用确认对话框，并明确说明影响范围。
- 操作反馈使用顶部轻量提示条或状态栏，自动消退的提示仍应能被 VoiceOver 读取，且不要让正文发生明显跳动。
- 主题切换时保留详情滚动状态的恢复策略，加载目标楼层时显示“正在定位到第 N 层”，失败时提供重试和回到顶部。

**长帖专用控制建议：**

- “加载更多”按钮旁同时显示已加载范围，例如“已显示 1–80 / 4,119 层”。
- 当用户接近当前已加载内容底部时，显示一次非打断式提示，而不是自动连续请求。
- 对跨页的目标楼层，先请求目标页，再定位到对应楼层；定位失败时不要把用户强制带回顶部。

### 5.4 正文 WebView `CookedHTMLView`

**建议：**

- 继续沿用系统字体、动态明暗配色和 `LDOTheme.readerMaxWidth`，正文最大宽度不随窗口无限拉伸。
- 正文链接、引用、代码块、表格、图片和附件需要保持明确的层级，但避免重边框和高对比阴影。
- 代码块提供横向滚动，不压缩正文布局；长链接允许换行，避免撑破阅读宽度。
- 图片加载中、加载失败和点击放大状态需要可识别的文字或图标提示，不显示原始文件名、分辨率等无关元数据。
- 选中、复制、打开外链和图片查看应遵循 macOS 默认行为；外链动作提供“在默认浏览器打开”的明确语义。
- 通过 JavaScript 注入的主题状态需要保持幂等，楼层分页或主题刷新后不能重复叠加样式和事件。
- 长帖更新时先保存滚动锚点，再插入内容并恢复锚点，避免正文突然跳动。

### 5.5 通知、资料和设置

- 通知列表沿用主题列表的扫描逻辑，未读状态使用图标、文字和系统选中态共同表达。
- 用户资料页优先展示身份、等级、注册时间、近期活动等高价值信息，徽章、解决方案等低频内容放入分区或 Sheet。
- 设置页使用原生 `Form` 和分区标题；外观、高亮、关键词、会话与数据清理分别成组。
- 关键词配置行应明确显示“启用状态、关键词文本、颜色、删除操作”，不要只靠色块让用户理解规则。
- 所有清除会话、删除本地数据等不可逆操作必须显示影响范围和确认按钮；取消按钮使用系统取消快捷键。
- 设置项默认值应服务于阅读，不要让用户首次打开就面对过多开关。高亮能力可以默认开启，但提供统一的“恢复默认设置”。

## 6. 工具栏与操作层级

建议按频率分层：

| 层级 | 放置位置 | 操作 |
| --- | --- | --- |
| 高频 | 工具栏 | 刷新、回复、搜索或当前范围切换 |
| 中频 | 工具栏 `Menu` / 右键菜单 | 跳转楼层、标记已读、书签、复制链接 |
| 低频 | 详情菜单或站点入口 | 兼容网页、举报、分享、调试或会话检查 |
| 危险 | 确认对话框 | 删除、清除会话、清空本地数据 |

图标按钮必须提供 `.help` 和可访问性标签。带文字的按钮只用于“回复、重试、加载更多、登录”等需要明确意图的动作；刷新、复制、关闭、更多等应优先使用熟悉的 SF Symbols。

## 7. 视觉系统收敛建议

继续以 `DesignSystem.swift` 为唯一视觉常量入口，建议补充：

- 标准间距：4 / 8 / 12 / 16 / 24，避免在 View 内新增任意间距。
- 状态颜色语义：信息、成功、警告、错误，并为每种状态定义图标和文字使用规则。
- 主题行、楼层头部、状态栏、提示条的统一高度和内边距。
- 阅读正文的标题、正文、引用、代码、元信息字号层级。
- 选中、悬停、键盘焦点、禁用、加载中的状态样式。
- 主题高亮与系统选中态的合成规则，确保关注高亮不会覆盖选中态。

不建议新增：

- 逐行大圆角卡片、重复阴影、斑马纹列表。
- 大面积固定 RGB 背景色或仅为装饰增加的渐变。
- 用颜色单独表示未读、关注、错误或成功。
- 在页面正文中重复展示工具栏已有的操作。

## 8. 交互与可访问性要求

### 8.1 键盘和焦点

- `⌘R` 刷新当前上下文，刷新中保持焦点和选择稳定。
- `Esc` 关闭 Sheet、Popover、提示条或取消当前编辑状态。
- Enter 确认默认操作，`⌘Enter` 可作为回复编辑器发送快捷键，但必须提供设置或明确提示。
- 列表支持上下键导航，详情支持回到顶部、加载更多和跳转楼层。
- 所有可点击区域必须有可见或系统可识别的焦点状态。

### 8.2 动态字体和 VoiceOver

- 不使用依赖固定文本高度的布局；标题、错误信息和描述允许换行。
- 图标-only 按钮提供动作名称，例如“关闭提示”“打开更多操作”“刷新主题”。
- 未读数量、加载进度、目标楼层定位和操作结果提供可读文本。
- 颜色高亮必须伴随文字徽章、图标或语义标签。
- WebView 内容中的标题、链接、引用和代码块保持合理的 HTML 语义层级。

## 9. 实施顺序

### P0：信息层级和状态统一

- 在 `DesignSystem.swift` 增加状态、间距、焦点和正文层级常量。
- 为 `TopicDetailView` 增加轻量主题头部。
- 收敛详情工具栏，将低频操作移入菜单。
- 统一列表、详情、通知和设置的加载、错误、空状态和操作反馈。
- 补齐所有图标按钮的 `.help`、可访问性标签和默认/取消快捷键。

**验证方式：** 默认窗口、最小窗口、浅色模式、深色模式各检查一次；确认三栏结构、标题、提示条和底部状态栏没有重叠或跳动。

### P1：阅读效率和主题扫描

- 增加跳转楼层 Sheet/Popover。
- 增加阅读位置恢复和目标楼层定位提示。
- 优化 `TopicRowView` 的标题、元信息和指标布局。
- 补充列表右键菜单、键盘导航和主题级快捷操作。
- 统一关注高亮、关键词高亮、未读和选中态的优先级。

**验证方式：** 使用普通主题、长主题、超过 4,000 层的主题分别验证；检查分页、定位、刷新和滚动锚点恢复。

### P2：个性化和工作流

- 增加阅读字号、正文宽度、行距和紧凑度设置。
- 增加标记已读、书签和上次阅读位置的完整闭环。
- 评估主题详情独立窗口、多窗口和状态恢复。
- 根据真实使用数据调整默认栏宽和列表密度。

**验证方式：** 重新启动应用后验证偏好和阅读位置恢复；检查多个窗口之间选择状态和会话状态不互相污染。

## 10. UI 验收清单

- [ ] 默认窗口和最小窗口下三栏均可用，文本无重叠和裁切。
- [ ] 侧栏当前选中项、通知未读、账号状态和分类加载状态清楚可辨。
- [ ] 主题列表标题、作者、时间、回复数和高亮状态具备稳定层级。
- [ ] 详情页能识别主题标题、作者、分类、阅读进度和当前加载范围。
- [ ] 长帖可以加载更多、跳转指定楼层并恢复滚动位置。
- [ ] 刷新、失败、登录失效、分页和帖子操作反馈不会遮挡正文。
- [ ] 浅色、深色、系统字体放大下颜色和布局均自然。
- [ ] 所有图标按钮有帮助文本或可访问性标签，状态不只依赖颜色。
- [ ] 键盘可以完成主要浏览路径，Sheet 和对话框支持 Enter/Esc。
- [ ] WebView 中图片、链接、引用、代码、表格和长链接不会破坏阅读宽度。
- [ ] 通过仓库规定的 Xcode 构建命令验证通过。

## 12. 最终建议

下一轮 UI 工作建议优先完成 P0 和 P1 的交互基础，再决定是否加入更多个性化装饰。这个产品的核心竞争力是“持续阅读效率”和“原生 macOS 工作流”，不是视觉元素数量。只要三栏关系、主题扫描、长帖定位、状态反馈和键盘体验稳定，整体质感会比继续堆叠卡片、颜色和按钮更明显地提升。
